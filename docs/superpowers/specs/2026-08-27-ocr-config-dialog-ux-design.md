# OCR 解析配置弹窗「参数可用性」UX 设计

日期：2026-08-27
范围：`app/ui/widgets/ocr_parse_config_dialog.py`（独立识别程序 OcrMainWindow
「配置」按钮弹窗）+ `tests/ui/widgets/test_ocr_parse_config_dialog.py`
约束：不改引擎 / 主窗口 / 配置结构；置灰不改变 `get_config_patch` 输出语义。

## 背景

参数 tooltip 上线后，从使用者视角审视弹窗仍有四处体验缺口：

1. **无效状态无反馈**：默认「版面分析」关闭（整页模式）时，辅助内容 7 项
   完全不生效，但复选框看起来可用——用户勾选后的期望被悄悄辜负，只有读
   灰色小字才知道。
2. **tooltip 不可发现**：说明做好了，但没有任何线索告诉用户「悬停能看」。
3. **数值不直观且无校验**：像素上下限是裸数字（1605632 对用户无意义）；
   `0 = 官方默认回退`语义下 min > max 矛盾无提示——包括隐藏矛盾
   （min=0 回退 112896 时，max 设 50000 即矛盾）。
4. **修改不可见**：只有全局「重置」，看不出哪些参数偏离默认（如上次为
   省显存调低了像素上限，这次忘了）。

## 决策

1. **联动置灰**：`use_layout_detection` 未勾选 → 辅助内容 7 复选框
   `setEnabled(False)`，组内提示切为「未开启『版面分析』：本组设置暂不
   生效」；勾选 → 恢复可用，提示「过滤在逐块识别时应用」。勾选值保留
   （patch 照常输出），开启版面分析后立即生效。
2. **可发现性**：按钮区上方一行灰字「鼠标悬停参数名或控件可查看作用
   说明」（注册 `_hints` 随 apply_theme 刷新）。
3. **数值易用性 + 校验**：最大像素行加「官方默认 1605632 / 省显存
   1048576」两枚扁平预设按钮；`_validate() -> str` 按**生效值**比较
   （`eff_min = min or 112896`、`eff_max = max or 1605632`），矛盾时
   `_on_apply` 弹 `QMessageBox.warning` 阻止应用（不 emit、不 accept），
   消息说明 0 的回退语义。
4. **修改标记**：偏离 `defaults()` 的参数显示名追加「 *」（复选框追加到
   自身文本、数值行追加到行标签）；刷新时机 = 初始化（构造完成后统一
   接线）/ 全部 toggled、valueChanged 信号 / 重置后（经信号自动触发）。
   选星号而非变色：色弱友好、不与主题色耦合。底部灰字图例
   「带 * 的参数已偏离默认值（重置可恢复）」与决策 2 合成一行。

## 明确不做

单位后缀（标签已含「像素」）、ParamRow 抽象（17 个固定参数属过度设计）、
每参数单独重置、双设置入口合并（已定仅弹窗范围）。

## 测试要点

- 既有 `test_aux_group_hint_text` 更新为两态断言（关 →「暂不生效」；
  开 →「逐块」）；其余既有用例不受影响（已确认无按复选框文本断言）。
- 新增：置灰两态 + 值保留进 patch；可发现性文案存在；`_validate` 四组
  边界（默认合法 / 显式矛盾 / min=0+小 max 隐藏矛盾 / 双 0 回退合法）；
  矛盾时 monkeypatch QMessageBox 阻止 emit 与 accept；标记出现/消失/
  重置清除；预设按钮点击设值。
