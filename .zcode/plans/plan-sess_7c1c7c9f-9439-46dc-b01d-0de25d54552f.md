# 界面设计 bug 修复计划

审查确认了 10 个真实 bug（另有 2 项核实为误报：batch_add_progress 信号有测试依赖属设计保留、批量定时器有 clear_files/closeEvent 清理兜底）。按用户选择全部修复，含配置层。

## A. 界面层修复

**A1 (H1) GGUF「禁用动画」开关即时生效** — `app/ui/widgets/gguf_settings_page.py`
- GgufSettingsForm 创建 `sw_animations` 后连接 `toggled` → `AnimationManager.set_enabled(not checked)`（与 rapid_settings_dialog.py:68 行为一致，目前全库无任何调用点，开关只写配置不生效）

**A2 (H2)「测试连接」读表单当前值** — `gguf_settings_page.py` + `gguf_main_window.py`
- 信号改为 `test_connection_requested = Signal(str, int)` 携带 (host, port)
- 按钮点击从 `self.form.ed_host`/`self.form.ed_port` 取值（与 get_config_patch 同兜底逻辑）
- `_on_settings_test_connection(self, host, port)` 改用参数，不再读 `self.config`（现状：改 host/port 不保存就点测试，测的是旧地址）

**A3 (H3) n_gpu_layers 兜底 99 → 999** — `gguf_settings_page.py:897`
- 清空输入框保存时兜底值与其他所有位置（创建/加载/重置/TOOLTIP/默认配置）的 999 统一

**A4 (M1) 引擎对话框 warning 按引擎记录** — `engine_select_dialog.py`
- `self._warning_shown` 由 bool 改为 `set()`，`_confirm` 中按 `self._selected` 记录
- 修复：双引擎都不可用时，切卡后第二个引擎的依赖缺失警告不再被跳过

**A5 (M2) 对话框允许增长** — `engine_select_dialog.py:290`
- `setFixedSize(880, 640)` → `setMinimumSize(880, 640)`，缺项文本多行/高 DPI 时窗口可长高，底部「进入」按钮不再被裁

**A6 (M4 行序 + C3 死键联动)** — `gguf_settings_page.py`
- 移除「空闲卸载秒数」行（引擎赋值 `_idle_unload_seconds` 但从不使用，TOOLTIP 自述"预留项"）
- 行序自动变为 device→n_gpu_layers→max_tokens→temperature→timeout→offload，与代码声明顺序一致（原 row 9/10/11 视觉顺序与声明相反）

**A7 (L3) 卡片聚焦/选中描边区分** — `engine_select_dialog.py` `_apply_style`
- `:focus` 改用 `hover_border` 色；新增 `[selected='true']` 规则置于 `:focus` 之后保持选中态 accent（QSS 同特异性后写优先）
- `set_selected` 时同步 `setProperty("selected", ...)`

**A8 (L4) 移除文件后状态栏同步** — `gguf_main_window.py`/`rapid_main_window.py` 的 file_removed 处理器
- 移除后若列表仍有文件，状态栏显示新当前文件（实现时按两窗口现有处理器微调，不改变面板信号语义）

**A9 (L5) dropEvent 无 PDF 时 ignore** — `file_list_panel.py:608-617`
- 与 dragEnterEvent 判定对称：`if files: add_files; acceptProposedAction()` 否则 `event.ignore()`

**A10 (L6) checkedId 防御** — `gguf_settings_page.py:924-925`
- `max(0, checkedId())`，避免组内无选中项时静默取到错误几何/提示类型

**A11 (M5) 批量定时器加父对象 + 去死参数** — `file_list_panel.py`
- `QTimer(self)`；删除 `process_batch` 未使用的 `start_count` 参数及调用处

## B. 配置层修复

**B1 默认配置补键与清死键** — `app/utils/config_loader.py` `get_default_config()`
- gguf 节补：`timeout_seconds: 120`、`match_iou_threshold: 0.5`、`match_neighbor_radius: 50`（UI 已暴露、引擎已消费，但默认字典缺失）
- 顶层补：`appearance: {"animations_enabled": True}`
- 移除死键：gguf `idle_unload_seconds`、pdf `max_preview_size`、ocr 顶层 `lang`/`use_gpu`/`use_angle_cls`/`det_db_box_thresh`/`drop_score`（实现前先 grep 确认零消费方；rapid 工厂只读 `ocr.rapidocr` 子节）
- `_validate_config` required_keys 增加 `"appearance"`（老配置自动补默认值）

**B2 (C2) CPU 模式表单联动** — `gguf_settings_page.py`
- `rb_device_cpu.toggled` → 禁用（灰显）`ed_n_gpu_layers` 与 `sw_mmproj_offload`，与引擎强制 `n_gpu_layers=0`/`mmproj_offload=False` 一致；`_load_settings` 后同步一次初始状态
- TOOLTIPS 注明「CPU 模式下无效」

**B3 (C3) 引擎侧清死键** — `app/core/ocr_engine_gguf.py:153`
- 删除 `_idle_unload_seconds` 赋值（无任何消费方）
