# 修复 rapid 模式识别失败不可见问题

## 诊断结论
- **引擎层健康**：venv 中 rapidocr_onnxruntime 1.4.4 + onnxruntime 1.27.0 实测识别成功（合成图端到端），API/结果格式/预处理链路全部兼容
- **根因在 UI 管线（错误被吞）**，与你"表格空白无报错"的现象完全吻合：
  1. `batch_processor.process_one`（batch_processor.py:135-136）`except Exception` 吞掉所有异常 → 返回 `FileResult(success=False, error_msg=str(e))`，**不抛、不日志**
  2. `on_try_ocr._on_done`（rapid_main_window.py:751-756）**不检查 `result.success`** → 失败也显示"试识别完成 - 共 N 个字段" + 空表格（L757 的 except 是死代码）
  3. `_on_batch_done` 恒弹 InfoBar.success，失败原因不展示
  4. 识别路径零日志，失败无法追踪

## 修复内容

### A. 让识别失败可见（核心）
**A1** `app/ui/windows/rapid_main_window.py` `on_try_ocr._on_done`（L751-756）：
- `result.success == False` → `InfoBar.error("试识别失败", error_msg)` + 状态栏"试识别失败"
- `success == True` 但 `len(result.fields) == 0` → `InfoBar.warning("未识别到内容")`（区分"识别失败"与"区域确实空白"）
- 成功且有字段 → 现有逻辑

**A2** `app/core/batch_processor.py` `process_one` except 分支（L135-136）：
- 补 `logging.getLogger("PDFOCR").error(f"[process_one] 识别失败 {pdf_path}: {e}", exc_info=True)`——失败可追踪

**A3** `rapid_main_window.py` `_on_batch_done`：
- `fail > 0` 时改为 `InfoBar.warning("部分文件识别失败", 失败数 + 提示查看结果表格)`，不再恒弹成功

**A4** `on_try_ocr` L732-733：`build_template()`/`current_file()` 主线程调用补 try/except（防炸 Qt 槽）

### B. 检测与提示完善
**B1** `app/utils/engine_checker.py` `_check_rapidocr`：
- `find_spec` + `from rapidocr_onnxruntime import RapidOCR; RapidOCR()` 构造 try/except——构造失败时 `available=False + issues`（引擎选择对话框不再误报"就绪"；RapidOCR() 构造不加载模型，速度快，可接受）

**B2** `app/ui/widgets/loading_overlay.py` `_translate_error_enhanced`（L255 映射表）：
- 新增 `"no module named"` 分支（"依赖包缺失"文案 + 安装指引）**置于 "onnx" 关键字之前**——rapidocr 包缺失时不再命中"onnx"误导为 VC++ 运行库问题

### C. 测试
- `tests/ui/test_rapid_window.py`：新增 on_try_ocr 失败路径——monkeypatch `processor.process_one` 返回失败 FileResult → 断言 InfoBar.error 出现 + 状态栏"试识别失败"；空字段路径 → warning
- `tests/test_engine_checker.py`：`_check_rapidocr` 构造失败路径（monkeypatch `RapidOCR` 抛异常 → available=False）
- loading_overlay：新增 "no module named" 映射断言（如该文件有测试）

### D. 验证
1. `./venv/Scripts/python.exe -m pytest tests/ -q` 全量回归
